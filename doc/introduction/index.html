01 / Why Fiber

为热路径设计，
也为工程落地。

性能不是最后添加的选项，而是从所有权、内存模型和调度边界开始的系统选择。 Fiber Gateway 同时保留清晰的协程表达力，让复杂协议与生产生命周期仍然可以被理解和验证。

01

全栈协议，统一生命周期

HTTP/1.1、HTTP/2、HTTP/3、WebSocket、gRPC 与 TLS 共享同一套 EventLoop、Buffer 和取消语义，减少协议之间的适配层与隐式状态。

02

少分配，低争用

复用 IoBuf、池化存储与 intrusive 结构；以 owner EventLoop 本地更新替代热路径锁和原子争用，把动态分配留在真正需要的边界。

03

清晰的协程语义

Task、超时、Watch、WaitGroup 与异步同步原语围绕显式所有权构建，让并发代码保持线性可读，同时具备可靠的取消与关闭路径。

04

生产能力不止于网络层

Nacos 配置与服务发现、CAT 链路追踪、Prometheus 指标、结构化日志和 DNS 缓存已经进入同一工程体系，应用可以直接复用，而不是从零拼装。

02 / Architecture

从应用到 I/O，
每层各司其职。

分层不是为了制造抽象，而是为了稳定边界：应用只组合能力，协议层维护 wire state， 运行时负责调度与所有权，传输层与 Linux 内核高效对话。

03 / Request Flow

快，不代表
看不清发生了什么。

请求从接入、匹配到流式转发和观测结算，状态沿着明确边界向前推进。 下游背压、超时、连接复用和关闭行为都属于同一生命周期，而不是散落的回调。

01

Accept

监听 TCP 或 QUIC，TLS ALPN 自动进入 HTTP/1.1、HTTP/2 或 HTTP/3 协议状态机。

02

Route

按 Host、路径与配置快照选择处理逻辑、上游集群或嵌入式脚本。

03

Stream

请求与响应按流转发，连接池复用上游连接，背压贯穿读写两端。

04

Observe

指标、日志与 CAT trace 在既定所有权边界内完成记录、聚合与优雅排空。
