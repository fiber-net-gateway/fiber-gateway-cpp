## 3. 根因（Fiber 子模块，pin 270035b）

`~Http2SendAwaiter` → `cleanup(true)` 的隐含假设——**armed 的发送总能同步收回、hook 已回 Idle**——不成立：

1. `Http2Connection::cancel_queued_stream_send`（`src/http/Http2Connection.cpp:2164`）只同步回收三种状态：ConnectionWindow 等待、StreamWindow 等待、Queued（已编码，但尚未进入在途批次）；**`State::InFlight` 返回 false**——批次已进入连接的发送路径，不能按 Queued 方式同步撤回，需要等待写完成或连接关闭清理。
2. `cleanup(true)`（`include/fiber/http/detail/Http2SendAwaiter.h`）对返回值 `(void)` 无视，无条件 `owner_->stream().disarm_outbound(this)` → `Http2Stream.cpp:190` 断言 `state_ == Idle` 失败 → abort。
3. `ServerHttp2Request::cancel_queued_send`（`src/http/ServerHttp2Request.cpp:527`）在 `abort_reason_ != IoErr::None` 时提前返回 false。但正常的 `Http2Stream::close()` 会先调用 `cancel_stream_send()`，清理 Queued/窗口等待，再调用 request 的 abort 回调。因此，**不能据此认定“已 abort 的 Queued 发送销毁也必炸”**；原分析对这一窗口的判断不成立。
4. `Http2Connection::cancel_stream_send`（:2213，stream 关闭路径）对 InFlight 只是标记 `completion_result_`，不驱动同步完结。连接级 `abort_outbound()` 则会先关闭必要的 transport，再清理在途缓冲区和 hook；不能概括为所有关闭路径都只能异步回收。
5. `on_timeout`（Http2SendAwaiter.h）在取消失败时不 complete，避免立即释放仍被发送路径引用的 awaiter；析构没有继续挂起的选项。这说明需要独立的“放弃业务操作”接口。另需区分超时语义：当前取消失败后不记录 TimedOut，也不重新设置定时器，多批次发送仍可能继续，不能据此认定超时处理完全正确。

### 修复方向（源码核查后修订）

- **推荐：同步解绑 awaiter，保留在途批次**。采用原方案 A 的生命周期分离思路，但优先复用 stream 内的 hook 和空 `outbound_operation_`，无需另行分配 tombstone 对象。具体接口、状态转换及验证要求见第 7 节。
- **不采用原方案 B 的“直接回收 InFlight 并回滚窗口”**。在途数据可能部分写出，连接还依赖 hook 维护批次字节顺序；TLS 遇到 WouldBlock 后也会保存原 chain 的身份和待完成长度。拥有 encoded buffer 不等于可以安全撤回已提交的发送。
- 析构清理应基于 stream/connection 的真实发送状态，不依赖 request 的 `abort_reason_` 提前返回。是否整理两端的 `cancel_queued_send()` 包装函数属于实现细节，不能把删除提前返回作为本次根因修复。

按约定 Fiber 修复由用户亲自上游提交（`native/patches/` 仅作临时兼容补丁位）。

### 7.1 核查范围与结论

源码核查基线为已提交的 `bfa756a4`；与生产 pin `270035b7` 对比，`Http2SendAwaiter`、`Http2Stream`、`Http2Connection` 以及两端 request 的相关代码没有变化，核心缺陷仍存在。本节记录设计方案，不表示已经修改实现或通过动态复现；生产日志和二进制符号化沿用前文材料，未重新独立验证。

问题不要求多线程并发：同一事件循环内，发送进入 InFlight 后，外层 Task 被销毁即可触发。客户端与服务端共用 `Http2SendAwaiter`，Header、Body、Trailer 发送都应纳入修复范围，流式响应只是本次观察到的触发场景。第 4 节的具体请求及取消来源仍属于推断。

### 7.2 生命周期与必须保持的不变量

发送路径有两层回调：

```text
连接持有的 Http2OutboundHook（嵌入 Http2Stream，ctx_ 指向 stream）
  → Http2Stream::on_outbound_hook_send_done()
  → outbound_operation_.ops->on_send_done(outbound_operation_.ctx)
                                        ↑
                               指向 Http2SendAwaiter
```

`on_encode()` 已将本批次数据交给发送缓冲区，并不意味着 awaiter 的生命周期已经结束。`on_send_done()` 仍需访问 awaiter 的 `owner_`、`op_`，更新发送结果并恢复协程；多批次操作还可能再次调用 `on_encode()`。

仅执行过 `on_encode()` 不足以触发该问题：处于 Queued 时可以同步撤回。危险状态是 **InFlight 且尚未完成发送时 awaiter 被析构**。现有代码先在 `disarm_outbound()` 断言失败；如果仅跳过解绑，则后续回调会访问已经销毁的协程帧。

修复必须同时满足：

1. awaiter 析构返回前，不再有回调、定时器或延迟恢复任务引用它。
2. 在途 hook、发送缓冲区和传输层待完成状态继续存活，直至写完成或连接关闭。
3. 被放弃的操作不再编码下一批，也不能把旧批次的完成事件交给新操作。
4. 尚未完成的发送被放弃后，stream 进入取消状态，不允许继续使用可能已经消耗输入、但未提交业务完成状态的请求。
5. 正常完成路径保留 `disarm_outbound()` 的严格断言；不通过移除断言掩盖状态错误。

### 7.4 `abandon_outbound()` 的处理顺序

1. 校验 `outbound_operation_.ctx == ctx`；不匹配时不修改其他操作。取得局部 `Http2Stream::Lease`，避免关闭、detach 或同步回调导致清理过程中 stream 被销毁。
2. 记录操作是否仍有发送工作，然后先清空 `outbound_operation_`，切断 `on_encode`/`on_send_done` 到 awaiter 的绑定。必须先解绑，再调用可能触发同步回调的取消和关闭逻辑，避免向正在析构的 awaiter 重新投递恢复任务。
3. 根据状态处理发送资源：

   | 状态 | 处理 |
   |---|---|
   | Idle，且无窗口等待、无发送 kind | 已完成或未成功提交，按正常解绑语义结束，不额外取消已完成请求。 |
   | ConnectionWindow / StreamWindow 等待 | 移除等待状态及等待链表节点，清除发送 kind 和 pending bytes，不再编码。 |
   | Queued | 从发送队列移除 hook、释放未发送的 encoded chain，按既有取消/关闭语义退还窗口预留，hook 回到 Idle。 |
   | InFlight | 保留 hook、`inflight_wire_bytes_`、在途 chain 和窗口消耗；清除发送 kind 和 pending bytes，禁止编码后续批次。 |

4. 对尚未完成就被放弃的发送，将 stream 置为 Canceled；如尚未关闭且需要通知对端，通过现有关闭流程发送 `RST_STREAM(CANCEL)`。对端已 RST 或 stream 已关闭时，不重复发送。RST 排队失败也必须完成本地取消和资源清理；必要时走连接关闭路径，不能留下活动操作。
5. 结束前确保 awaiter 的 timer 和延迟恢复任务已取消，且后续关闭回调无法重新注册它们。同步调用应使用仍附着的 stream/connection 关系，不依赖已经脱离连接的 request 指针。

连接已经通过 `try_release_stream()` 阻止非 Idle hook 所属 stream 被 detach，正常在途期间可复用这一所有权保证。局部 Lease 用于保护本次同步清理；不需要为每个批次另行分配存活对象。

### 7.5 在途完成与重新提交约束

异步完成时仍由 `finish_written_outbound_hooks()` 按实际写入字节数维护 hook，完成后进入 `Http2Stream::on_outbound_hook_send_done()`：

- `notify_outbound_send_done()` 已支持 operation 为空时直接返回，可复用该行为，避免调用已销毁 awaiter 的 `op_.on_send_done()`。
- 放弃操作时必须主动清除 `outbound_kind_` 和 pending bytes，不能期待空 operation 的完成通知代为清除；否则 `on_stream_outbound_idle()` 可能再次编码。
- 保留后续 `on_stream_outbound_idle()` / `try_release_stream()` 路径，让已关闭 stream 在 hook 回到 Idle 后自然释放。
- 连接关闭路径也必须支持 operation 已为空的在途 stream。遵循现有 `abort_outbound()` 的顺序，在需要时先关闭 transport，再释放它可能引用的 chain。

`try_arm_outbound()` 不能只判断 operation 是否为空，还应拒绝 hook 非 Idle、仍有窗口等待、发送 kind 未清空或 stream 已关闭的情况。这样，即使旧批次尚在排空，也不会绑定新 awaiter 并把旧批次完成事件交给它。

### 7.6 不采用的局部修补与后续问题

- 不删除 `disarm_outbound()` 的 Idle 断言。
- 不在取消失败后仅跳过 `disarm_outbound()`：这会留下指向 awaiter 的悬空回调。
- 不只把回调换成 no-op 而保留续批状态：多批次发送还会触发 `on_encode()`。
- 不从连接在途列表中直接移除 hook，也不回滚已经进入在途批次的流控消耗。部分写入、TLS 重试状态和同连接其他 stream 的字节顺序必须保持一致。
- 不用每次取消都关闭整个连接替代 stream 级生命周期修复；正常取消应保持其他 stream 可用。

内部发送超时在 InFlight 时的结果语义另行设计和验证，本次不顺带改变 `on_timeout()` 的行为。析构放弃接口应能处理业务层超时导致的外层 Task 销毁。

### 7.7 验证与验收

使用 fake transport 明确控制写入进度，不依赖真实网络概率复现：

| 场景 | 主要断言 |
|---|---|
| 首次写返回 WouldBlock，销毁发送 Task，再允许写入 | 析构无断言；不再访问 awaiter；在途批次可排空。 |
| 部分字节写出后 WouldBlock，再销毁 Task | 剩余字节及 hook 记账一致，不重复发送、不退还在途窗口；同连接其他 stream 正常完成。 |
| 多批次 `write_all` 首批在途时销毁 | 不再访问原 `op_` 或编码后续批次，剩余业务输入可释放。 |
| 分别在 Queued、两种窗口等待、InFlight 时收到 RST 并销毁 | 各状态正确退出，无残留等待节点、重复完成或悬空回调。 |
| 正常完成已投递恢复任务，但 Task 在恢复前被销毁 | 恢复任务被取消，不误取消已完成发送，不恢复已销毁协程。 |
| Task 销毁后立即关闭连接，或 RST 排队失败 | transport/chain 释放顺序正确，stream 最终释放，无资源泄漏。 |
| 放弃后立即再次提交发送 | 旧在途批次不能关联新 awaiter；已取消 stream 拒绝新写入。 |

测试应覆盖客户端和服务端，以及 Header、Body、Trailer 的共同析构路径。对本次生产场景增加服务端 `write(IoBufChain&)` 的专门用例；对续批增加 `write_all` 用例。配合 ASan 检查 UAF，并通过销毁计数及队列/窗口断言检查资源释放和记账。

| `include/fiber/http/Http2Stream.h`、`src/http/Http2Stream.cpp` | 新增 `abandon_outbound()`；`try_arm_outbound()` 改返回 `IoErr` 并加强校验；`close_rst()` 对已 reset 的 stream 不再发 RST |
| `include/fiber/http/Http2Connection.h`、`src/http/Http2Connection.cpp` | 新增 `drop_outbound_hook()`，`abort_outbound()` 丢弃 stream hook 时通知写操作（8.4） |

两端 request（`ServerHttp2Request`、`ClientHttp2Request`）未修改。它们的 `cancel_queued_send()` 包装仍供 `await_ready()`（timeout 为 0）和 `on_timeout()` 使用，析构路径不再调用。

### 8.2 析构放弃：按第 7 节实现的部分

- **`Http2SendAwaiter::cleanup()`**：`cleanup(false)`（`await_resume()`）仍调用 `disarm_outbound()`，Idle 断言原样保留；`cleanup(true)`（析构）改调 `abandon_outbound()`。timer 和恢复任务照旧先取消。
- **`Http2Stream::abandon_outbound()`**，与 7.4 一致：
  1. ctx 不匹配直接返回；取局部 `Lease`。
  2. 记录是否仍有发送工作，然后**先清空 `outbound_operation_`**，再做任何可能回调的操作。
  3. 无发送工作（已完成、恢复任务未执行）：只解绑，不取消 stream。
  4. 等窗口或 Queued：复用 `Http2Connection::cancel_queued_stream_send()` 撤回。它会同时退还连接窗口和 stream 窗口，stream 随后被 RST。
  5. InFlight：保留 hook、`inflight_wire_bytes_`、在途 chain 和窗口消耗，只清 kind 和 pending bytes。批次写完后，`on_outbound_hook_send_done()` 见 operation 为空直接返回；`on_stream_outbound_idle()` 见 stream 已关闭不再编码，并释放 stream。
  6. stream 已关闭（对端 RST 等）：不再发 RST，只尝试释放。否则 `close_rst(Cancel, Canceled)`。
  7. RST 排不进队：本地 `close(Canceled)`；连接仍在发送（`!outbound_closed_`）时 `enter_closing(err)`，否则只释放 stream。
- **`try_arm_outbound()`**：返回值由 `bool` 改为 `IoErr`。operation 未解绑、hook 非 Idle、仍在等窗口或 kind 未清空时返回 `Already`；stream 已关闭时返回 `close_reason_`。旧在途批次排空期间不能绑定新 awaiter。
- **`Http2Connection`**：这一部分没有新增接口，复用 `cancel_queued_stream_send()`、`try_release_stream()`、`enter_closing()`（`Http2Stream` 是友元）。

与第 7 节的偏差：

- **`close_rst()` 去重**：stream 已被任一方 reset 时直接返回 `None`，不再发送 RST_STREAM。原因：放弃之后业务如果再写，`HttpExchange::record_response_write_error()` 会调 `abort()` → `close_rst()`，在已关闭的 stream 上再发一个 RST，违反 RFC 9113 §5.1。所有调用方（`ServerHttp2Request::abort()`、`ClientHttp2Exchange::abort()`、`ClientHttp2Request::record_request_write_error()`、`run_handler_task()`）都把 `None`/`Canceled` 视为成功。
- **`loop_` 改动**：工作区原有一处未完成的改动——`loop_` 改成引用但未在构造函数初始化，并在 `await_suspend()` 里对引用赋值，无法编译。现改为构造时绑定 `EventLoop::current()`；是否已投递恢复任务改用 `notify_entry_.is_in_queue()` 判断，去掉 `resume_posted_`。

### 8.3 为什么修复有效

析构时切断的是 stream 到 awaiter 的唯一引用（`outbound_operation_`）。在途批次继续由连接持有，完成时只会看到空 operation；连接关闭时 `abort_outbound()` 先关 transport 再释放 chain，顺序不变。第 7.2 节的五条不变量：

| 不变量 | 实现 |
|---|---|
| 1. 析构后无回调、定时器、恢复任务引用 awaiter | `cleanup()` 取消 timer 和恢复任务；`abandon_outbound()` 第一步解绑 |
| 2. 在途 hook、缓冲区、传输层状态存活 | InFlight 分支不动 hook 和 chain |
| 3. 不续批、不把旧完成交给新操作 | kind 清空；`try_arm_outbound()` 拒绝非 Idle hook |
| 4. 放弃后 stream 取消，拒绝后续写入 | `close_rst()` → request 的 `abort_reason_`；后续写返回 `Canceled` |
| 5. 保留 `disarm_outbound()` 断言 | 未改动 |

### 8.4 顺带修复：连接中止丢弃在途批次时，写操作永久挂起

实施过程中发现的另一个缺陷，与本次崩溃同一触发面（客户端 RST + 连接断开），但不是崩溃原因。

- **触发条件**：写批次在途时，stream 先被关闭（对端 RST 或本地 `close_rst()`）；随后连接在这批写完之前中止（传输错误、`shutdown()`、连接析构）。
- **表现**：连接已 `Closed`、stream 已脱离连接，但挂着的 `write` 永不返回；它自己的超时也救不回来，因为 request 已 abort 时 `cancel_queued_send()` 直接返回 false。handler 协程和 request 随之泄漏。修复前用临时用例复现确认。
- **根因**：`abort_outbound()` 是唯一一处不给完成通知就丢弃 stream hook 的地方。stream 在在途期间第一次关闭时，`cancel_stream_send()` 只在 hook 上记 `completion_result_`，等批次写完再通知；批次被丢弃后这次通知永远不会来，之后 `close_all_streams()` 的第二次 `close()` 也不再通知。
- **修复**：`abort_outbound()` 的排队、在途两段清理改为调用新的 `Http2Connection::drop_outbound_hook()`。它照旧复位 hook、清 kind，并调用 `stream->notify_outbound_send_done()` 通知写操作：
  - stream 已关闭：返回 hook 上记的关闭原因（如对端 RST 的 `Canceled`），与批次正常写完时的结果一致。
  - stream 未关闭：返回连接的停止原因。每条中止路径里这个值与随后 `close_all_streams()` 用的值相同，行为不变；随后的第二次通知被 awaiter 的 `completed_` 挡掉。
- **不采用直接调用 `send_done_cb_`**：它会走 `on_stream_outbound_idle()` → `try_release_stream()` → `detach_stream()`，Closing 状态下再进 `finish_connection()`，在 `abort_outbound()` 遍历途中（含连接析构）重入 `close_all_streams()`。现在只通知写操作本身，awaiter 只投递恢复任务，不回到连接。
- 等窗口的 stream 不需要处理：已关闭的 stream 不会还在等窗口；未关闭的由 `close_all_streams()` 通知，而每条中止路径都会走到它。

## 9. Review 补充修复：首个 HEADERS 未发送时只做本地关闭

第 8 节的实现仍有一个客户端边界问题：首个请求 HEADERS 处于 Queued 时销毁发送 Task，`abandon_outbound()` 会撤回 HEADERS，然后发送 RST_STREAM。对端尚未见过该 stream，收到这个 RST 会按 idle stream 协议错误关闭整条连接。Review 已用真实 `ClientHttp2Exchange::send_request_header()` 的临时用例复现，并把客户端输出交给本仓库的服务端解析，得到 `IoErr::Invalid`。

### 9.1 实现

- `Http2Stream` 增加 `opening_committed_`，初始为 false。它表示建立流的 HEADERS 已收到，或者已提交到必须排空的在途批次；不表示数据一定已到达对端。
- `Http2Connection::create_peer_stream()` 将其设为 true：对端已发起请求，服务端可以在发送响应头之前 reset。
- `build_outbound_batch()` 将 HEADERS hook 转为 InFlight 时将其设为 true。不能等 `on_send_done()` 才设置，否则 HEADERS 部分写出时会被误判为尚未建立。
- `Http2Stream::close_rst()` 统一检查该标记。false 时仅调用本地 `close()` 和 `try_release_stream()`，不发送 RST，也不设置 `local_rst_`；true 时保留原来的 RST 发送流程。局部 Lease 保护关闭回调期间的 stream 生命周期。
- `abandon_outbound()` 继续使用 `close_rst()`，显式 `abort()` 同样走这条路径，无需分别增加协议判断。在途 hook、chain、窗口及回调解绑逻辑保持第 8 节的行为。

原 DATA-only raw 测试通过 fixture 明确模拟已经建立的流，观测建立之后的流量；新增边界测试使用真实 request/exchange API。
