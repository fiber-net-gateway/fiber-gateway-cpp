# Upstream provenance: zlib 1.3.2

The DEFLATE core in this directory, the CRC32 backend in
`src/common/util/`, and the gzip framing in `GzipEncoder` are ports of
**zlib 1.3.2** by Jean-loup Gailly and Mark Adler (license: `LICENSE.zlib`
next to this file; upstream archive: https://zlib.net/zlib-1.3.2.tar.gz,
SHA-256 `bb329a0a2cd0274d05519d61c667c062e06990d72e125ee2dfa8de64f0119d16`).

The port is line-oriented, not byte-oriented: control flow, invariants and
comments follow upstream closely so that future zlib fixes can be diffed in,
while the surrounding API is idiomatic C++23 for this project. Any deviation
must be justified in this file.

## File map

| This project | zlib 1.3.2 | Notes |
| --- | --- | --- |
| `src/compression/DeflateTables.h` | `trees.h` + `tr_static_init()` in `trees.c` | Static tables are constexpr-generated by the same algorithm instead of transcribed; values verified equal to the shipped `trees.h`. |
| `src/compression/DeflateState.h` | `deflate.h` | `internal_state` with removed features dropped; fixed parameters (windowBits 15, memLevel 8, levels 1..9). |
| `src/compression/DeflateTrees.cpp` | `trees.c` | Huffman construction, bit-length serialization, block emission. |
| `src/compression/DeflateEncoder.cpp` | `deflate.c` | `deflate()` driver loop, `deflate_fast`/`deflate_slow`, `fill_window`, `longest_match` (portable variant), `lm_init`, `slide_hash`. |
| `src/compression/GzipEncoder.cpp` | gzip parts of `deflate.c` (`GZIP_STATE` header, trailer) | RFC 1952 framing around the raw core. |
| `src/common/util/Crc32.{h,cpp}`, `detail/Crc32Tables.h` | `crc32.c`, `crc32.h` | Braided N=5 portable backend (no hardware CRC32). |

## Deliberate deviations

* **Removed features**: zlib/gzip wrappers inside the core (the raw core
  emits a bare DEFLATE stream; `GzipEncoder` adds the gzip member), the
  stored-only level 0 driver, `deflate_rle`/`deflate_huff` strategies,
  preset dictionaries, `deflateCopy`/`deflatePrime`/`deflateParams`/
  `deflateTune`/`deflatePending`/`deflateBound`, `gz_header` fields,
  `detect_data_type` (observable only through removed APIs), the
  `matches`/`bi_used`/debug counters, and `UNALIGNED_OK`/`LIT_MEM` variants.
* **Fixed parameters**: windowBits 15, memLevel 8, default strategy only,
  levels 1..9. All parameter-dependent code paths were reduced to constants
  (`DeflateState.h`).
* **Resumable operations**: `z_stream` and the single-shot `deflate()` entry
  point became `DeflateEncoder::write/flush/finish` returning
  `EncodeStep{consumed, written, status}`. The mapping preserves zlib's
  resumability machinery exactly: the initial pending drain before any other
  work, `RANK()`-based duplicate-flush suppression, the `last_flush == -1`
  sentinel set after a partial pending drain, and the `FINISH_STATE` guard
  against re-entering the block drivers after the final block started.
  Zero-length output spans are legal (upstream returns `Z_BUF_ERROR` there;
  callers in this project must make progress with tiny buffers instead).
* **CRC/length accounting** moved to `GzipEncoder` and covers exactly the
  bytes reported consumed (upstream updates them in `read_buf`).
* **Types**: fixed-width integers; `ulg` -> `uint64_t`, `block_start` and
  `high_water` tightened to 32 bits with proven ranges.
* **Allocation**: the four upstream buffers (window, prev, head, pending)
  keep their sizes and the pending/sym_buf overlay, but live in one
  caller-provided workspace block instead of four heap allocations.
* **Tables**: `static_ltree`/`static_dtree`/`_dist_code`/`_length_code`/
  `base_length`/`base_dist` are `constexpr` generated by the upstream
  generator algorithm at compile time (mirroring the non-STDC path of
  `tr_static_init`), not hand-copied.

## Tests reference the real thing

`tests/support/third_party/zlib_1_3_2/` keeps an unmodified copy of the
zlib 1.3.2 sources (see its `manifest.sha256` and `README.md`), compiled
with a symbol prefix and exposed through `support/ZlibReference.h` as the
differential oracle for these ports. Update policy and build configuration
are documented there.
